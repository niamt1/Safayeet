How to use: For each section, first read the original slide points, then study the explanation, and finally practice with the exam focus note.

Slide 1

Uses of Computer Networks

Original points preserved

  • Business Applications Home Applications Mobile Users Social Issues

In-depth explanation

Computer networks enable resource sharing, communication, distributed computation, and global coordination. At a systems level, networking converts isolated machines into a cooperative platform where applications can be split across devices while still behaving like one logical system.

Exam focus: For exams, be able to classify network uses into business, home, mobile, and societal impacts, and explain why packet switching and protocol standardization make these uses scalable.
Slide 2

Business Applications of Networks

Original points preserved

  • A network with two clients and one server.

In-depth explanation

In enterprises, networks support shared databases, ERP systems, cloud services, and collaborative workflows. Client devices consume services exposed by servers (authentication, storage, analytics). This architecture centralizes policy enforcement, backups, auditing, and access control.

Exam focus: Know why organizations prefer centralized servers: easier updates, stronger security controls, and better data consistency under concurrent access.
Slide 3

Business Applications of Networks (2)

Original points preserved

  • The client-server model involves requests and replies.

In-depth explanation

The request-reply cycle is the core interaction pattern in distributed systems. A client sends a request message, the server validates identity/authorization, executes logic, and returns a response. Latency, throughput, and failure handling determine user-perceived performance.

Exam focus: Practice drawing sequence diagrams for client-server exchange and identify where timeout, retransmission, and idempotency are needed.
Slide 4

Home Network Applications

Original points preserved

  • Access to remote information Person-to-person communication Interactive entertainment Electronic commerce

In-depth explanation

Home networking covers information access (web, cloud storage), person-to-person communication (voice/video/chat), entertainment streaming, and e-commerce. The home router acts as gateway, firewall, DHCP server, and often Wi‑Fi access point.

Exam focus: Be able to connect application examples to underlying protocols (e.g., HTTPS for commerce, RTP/QUIC for media, DNS for name resolution).
Slide 5

Home Network Applications (2)

Original points preserved

  • In peer-to-peer system there are no fixed clients and servers.

In-depth explanation

Peer-to-peer systems distribute responsibility among peers: each node can be both client and server. This improves scalability and resilience but complicates trust, NAT traversal, and content discovery.

Exam focus: Understand tradeoffs: P2P reduces central bottlenecks but makes consistency, moderation, and security harder.
Slide 6

Home Network Applications (3)

Original points preserved

  • Some forms of e-commerce.

In-depth explanation

E-commerce includes storefront browsing, payment authorization, inventory checks, shipping orchestration, and after-sales support. Security depends on TLS, certificate validation, secure session handling, anti-fraud analytics, and regulatory compliance.

Exam focus: For exam answers, discuss confidentiality, integrity, authentication, and non-repudiation in online transactions.
Slide 7

Mobile Network Users

Original points preserved

  • Combinations of wireless networks and mobile computing.

In-depth explanation

Mobility introduces variable bandwidth, intermittent connectivity, handoff delays, and energy constraints. Wireless + mobility combinations range from stationary wireless users to fully mobile users with always-on cellular data.

Exam focus: Differentiate mobility management (keeping identity/session while moving) from mere wireless access (radio medium).

Network Hardware

Original points preserved

  • Local Area Networks Metropolitan Area Networks Wide Area Networks Wireless Networks Home Networks Internetworks

In-depth explanation

Hardware is categorized by scale and technology: LAN, MAN, WAN, wireless, home networks, and internetworks. Devices include hosts, switches, routers, access points, and middleboxes; links may be copper, fiber, or radio.

Exam focus: Be able to justify device placement: switching inside LANs, routing between networks, and gateways for protocol boundaries.
Slide 9

Broadcast Networks

Original points preserved

  • Types of transmission technology
  • Broadcast links Point-to-point links

In-depth explanation

Broadcast links share one transmission medium among many nodes; addressing in frame headers decides who should process each frame. Point-to-point links dedicate connectivity between pairs of nodes and are composed into larger topologies.

Exam focus: Know where broadcast is efficient (small LAN discovery) and where it is problematic (scalability, collisions, security exposure).
Slide 10

Broadcast Networks (2)

Original points preserved

  • Classification of interconnected processors by scale.

In-depth explanation

Processor/network classification by scale helps choose technology and protocol assumptions: short distances allow lower latency and high bandwidth sharing; larger scales require routing, hierarchy, and fault isolation.

Exam focus: Map each scale to typical examples: LAN in buildings, MAN across city, WAN across regions/countries.
Slide 11

Local Area Networks

Original points preserved

  • Two broadcast networks
  • Bus Ring

In-depth explanation

Classic LAN topologies include bus and ring, while modern LANs are mostly switched star Ethernet. LANs emphasize high speed, low error rate, and organizational control over infrastructure.

Exam focus: Explain why switched Ethernet replaced shared bus: fewer collisions, full-duplex links, and easier scaling.
Slide 12

Metropolitan Area Networks

Original points preserved

  • A metropolitan area network based on cable TV.

In-depth explanation

MANs interconnect multiple LANs across a city, often using provider infrastructure like cable/fiber rings. They balance regional coverage and higher bandwidth than long-haul WANs.

Exam focus: Expect questions comparing MAN vs WAN in ownership, latency, and technology choices.
Slide 13

Wide Area Networks

Original points preserved

  • Relation between hosts on LANs and the subnet.

In-depth explanation

WANs connect distant sites through carrier networks. Hosts attach to edge routers; routers form a subnet that forwards packets hop-by-hop using routing tables and control protocols.

Exam focus: In answers, distinguish hosts (end systems) from the communication subnet (routers + links).
Slide 14

Wide Area Networks (2)

Original points preserved

  • A stream of packets from sender to receiver.

In-depth explanation

Packets from one flow can take dynamic paths depending on congestion or failures. Store-and-forward forwarding introduces queueing and serialization delays at each hop.

Exam focus: Be prepared to compute end-to-end delay components: processing + queueing + transmission + propagation.
Slide 15

Wireless Networks

  • System interconnection Wireless LANs Wireless WANs

In-depth explanation

Wireless systems can be grouped as short-range interconnection (e.g., Bluetooth), WLAN (Wi‑Fi), and WWAN (cellular). Shared spectrum and interference make MAC design critical.

Exam focus: Know core challenges: fading, hidden terminals, contention, and mobility support.

Bluetooth uses piconets/scatternets for personal-area connectivity, while WLANs provide higher throughput and IP connectivity in local coverage zones.

Exam focus: Compare Bluetooth and Wi‑Fi by range, data rate, power profile, and common use cases.

In-depth explanation

Design Issues for the Layers

Original points preserved

  • Addressing Error Control Flow Control Multiplexing Routing
  • Connection-Oriented and Connectionless Services
  • Six different types of service.

In-depth explanation

Key layer concerns include addressing (who), error control (correctness), flow control (rate matching), multiplexing (sharing channels), and routing (path selection). These appear repeatedly across layers with different mechanisms.

Exam focus: A strong answer connects each issue to a concrete protocol example (e.g., TCP flow control, IP routing, MAC addressing).
Slide 21

Service Primitives

Original points preserved

  • Five service primitives for implementing a simple connection-
  • oriented service.

In-depth explanation

Service primitives are abstract operations offered by a layer, such as LISTEN, CONNECT, SEND, RECEIVE, and DISCONNECT. They define API-level behavior independent of wire-level protocol details.

Exam focus: Differentiate service specification (what operations do) from protocol implementation (how messages realize them).
Slide 22

Service Primitives (2)

Original points preserved

  • Packets sent in a simple client-server interaction on a connection-oriented network.

In-depth explanation

In connection-oriented exchange, setup precedes data transfer and teardown follows completion. Control packets establish state; data packets use this state for reliable ordered delivery.

Exam focus: Sequence reasoning is frequently tested—practice identifying which packet corresponds to which primitive.
Slide 23

Services to Protocols Relationship

Original points preserved

  • The relationship between a service and a protocol.

In-depth explanation

A service is the contract between adjacent layers; a protocol is the rule set among peer entities at the same layer. Good architecture separates these to enable replacing protocols without breaking upper layers.

Exam focus: Expect conceptual questions asking why service/protocol/interface separation improves maintainability.

ATM uses virtual circuits with pre-established paths and per-hop labels, enabling predictable QoS and traffic engineering. State in switches supports connection semantics.

Slide 39

ATM Virtual Circuits (2)

Original points preserved

  • An ATM cell.

In-depth explanation

ATM cells are fixed-length (53 bytes: 5-byte header + 48-byte payload), which simplifies switching hardware and delay predictability but adds overhead for small payloads.

Exam focus: Be able to compute header overhead and discuss tradeoffs of fixed-size cells.

Metric Units

Original points preserved

  • The principal metric prefixes.

In-depth explanation

Networking performance uses SI prefixes (kilo, mega, giga, tera, etc.) for rates, frequencies, and capacities. Distinguish decimal SI (10^3) from binary prefixes (Ki, Mi, Gi = 2^10, 2^20, 2^30).
